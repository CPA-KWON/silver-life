# 활동 미션 · 동네 경험 은행

기준 코드: `design/ppt-ui-refresh` / `7953f5f`의 v5 디자인.
작업 브랜치: `feature/activity-missions-experience-bank`.

## 구현한 흐름

- 홈의 인사말·다가오는 모임·빠른 실행·주변 시설·즐겨찾기·최근 커뮤니티 글을 유지하고 활동 미션·경험 은행 진입 카드 추가.
- 내 정보의 활동 메뉴에서도 내 신청·참여 이력으로 이동.
- 활동 설정: 관심 분야, 기준 시설, 직선거리 1/3/5/10/20km, 도보·대중교통·자동차, 혼자·함께·무관, 최대 활동시간, 난이도, 새로운 활동 선호.
- 맞춤 추천은 실제 모집 여부·잔여 정원·마감·거리·관심 분야·교통·참여 방식·시간·난이도를 모두 확인. 반경은 자동 확대하지 않음.
- 적합한 후보 안에서 계약·입금 확인 후 활성화된 기관 후원 활동을 먼저 노출하고 `기관 후원 · 우선 노출` 표시. 그다음 미경험 분야·거리·일정 순으로 정렬.
- 주간 미션은 한국시간 월요일 기준. 이번 주 실제 활동을 익숙한 동네 → 새로운 장소 → 함께하는 활동 순으로 최대 3단계 저장. 날짜가 겹치지 않으며, 첫 단계 후보가 없으면 임의로 다음 단계부터 만들지 않음.
- 새로운 활동 옵션을 끄면 1단계만 생성. 가까운 곳에서 반복 참여하는 선택도 지원.
- 같은 주 미션 만들기는 중복 생성하지 않음. `신청 전 미션 다시 고르기`는 미신청·취소·반려된 미션만 재선정하고 이미 신청·승인·완료된 미션과 이력은 유지.
- 전체 활동과 경험 나눔 모집은 전체 지역 목록으로, 맞춤 추천과 다름을 안내.
- 경험 등록·수정·휴식 상태 전환. 경험은 본인만 조회할 수 있고, 같은 분야의 기관 모집에 지원할 때 제출 내용을 기관에 전달.
- 제출한 경험은 서버가 신청 당시의 사본을 기록하므로 이후 경험을 수정해도 기존 지원서가 바뀌지 않음.
- 기관 담당자가 신청 승인·반려·실제 활동 완료 확인. 완료 확인은 활동 종료 후에만 가능. 본인 신청의 완료 확인과 소속 기관의 경험 나눔 지원은 차단.
- 경험 나눔 완료 1건당 30일간 50% 혜택 발급. 겹쳐도 50%를 초과하거나 기간을 합산하지 않음. 가장 늦은 유효 만료 시각까지 적용.
- 혜택 기간에 새로 신청하는 모든 유료 **기관 프로그램**에 적용. 무료는 무료 유지. 홀수 원의 절반은 최종 참여비를 올림(5,001원 → 2,501원).
- 신청 시 서버 시각과 DB 가격으로 금액 확정. 클라이언트가 할인율·금액을 지정할 수 없음. 혜택 만료로 기존 신청 금액이 변하지 않으며 취소 후 재신청은 당시 조건으로 다시 계산.
- 기존 사용자 작성 동네모임에는 참여비 체계가 없어 이번 할인에 편입하지 않음.
- 기관 운영: 프로그램·경험 나눔 모집 등록, 모집 마감, 신청 처리, 실제 참여·재참여·활동 분야 통계.

## 서버 구조와 권한

`supabase/activity_expansion.sql`은 신규 테이블 9개와 신규 함수·정책만 추가한다. 기존 profiles·posts·comments·facilities·favorites·checkins 및 기존 RLS를 변경하지 않는다.

기관·기관 담당자·후원·혜택·미션·신청 상태를 일반 사용자가 직접 조작할 수 없도록 직접 쓰기 권한을 주지 않는다. 신청·취소·기관 처리·프로그램 등록은 인증된 RPC로 수행한다. 프로그램 행 잠금으로 동시 신청의 정원 초과를 막는다.

기관 통계의 실제 참여율은 **종료된 활동의 승인·완료 신청 중 완료 비율**이다. 재참여율은 **완료 경험이 있는 사람 중 2회 이상 완료한 사람의 비율**이다. 분모가 없으면 집계 전으로 표시한다. 활동 다양성은 완료된 활동의 서로 다른 분야 수이다.

## 실제 서비스 적용 전 필요한 작업

아래 항목은 아직 수행하지 않았다. 이 파일이나 GitHub 업로드로 자동 실행되지 않는다.

1. 사용자 승인 후 실제 DB 백업과 기존 권한 검토.
2. Supabase SQL Editor에서 `activity_expansion.sql` 검토 후 한 번 적용. 중복 실행용 migration은 아니다.
3. 관리자가 검증한 기관을 `activity_organizations`에 등록하고 `approved=true` 설정.
4. 관리자가 실제 담당자 계정을 `activity_org_members`에 연결. 일반 사용자는 스스로 기관 권한을 얻을 수 없다.
5. 담당자가 앱에서 실제 프로그램 등록.
6. 후원 계약과 입금 확인 후 관리자가 `activity_sponsorships`의 대상·기간·payment_confirmed 설정. 입금 전·기간 전·만료 후에는 우선 노출하지 않음.
7. 일반 계정과 기관 계정으로 실환경 신청·승인·완료·혜택 흐름 검증.

DB가 준비되지 않았으면 신규 화면에 서비스 준비·연결 안내와 재시도 버튼을 표시한다. 기존 홈 조회는 신규 RPC에 의존하지 않는다. 예시 프로그램을 실제 DB에 자동 입력하지 않는다.

## 구현 범위의 제한

- 카드 결제·정산·자동 환불·후원비 온라인 결제는 구현하지 않음. 앱에서는 신청 금액을 확정하며 실제 납부는 기관 안내를 따른다.
- 할인 차액을 플랫폼·기관·후원 예산 중 누가 부담할지는 운영 계약으로 확정해야 함.
- 외부 기관 사이트의 신청 API·자동 프로그램 수집·길찾기 소요시간·동행자 자동 매칭·푸시 알림은 포함하지 않음.
- `함께`는 단체 참여 가능한 활동을 뜻하며 특정 동행자를 매칭하지 않음.
- 네이버 지도·GPS의 핵심 로직과 기존 로그인·게시글·모임 CRUD를 유지한다. 주변 화면의 오류·연결 보완 내역은 `qa_audit.md` 참조.
- 팀 저장소의 신규 커밋을 병합하지 않았으며 신고 기능은 이번 브랜치에 새로 가져오지 않음.

## 검증 명령

Flutter 3.47.7 / Dart 3.13.5에서 검증하며 프로젝트의 pubspec과 lock은 변경하지 않았다.

```bash
flutter pub get
CI=true BOT=true FLUTTER_SUPPRESS_ANALYTICS=true flutter analyze --no-pub lib test
CI=true BOT=true FLUTTER_SUPPRESS_ANALYTICS=true flutter test --no-pub --concurrency=1
```

SQL 검사는 실제 서비스에 접속하지 않는 일회성 PostgreSQL(PGlite)을 사용한다.

```bash
# 별도 임시 디렉터리에 npm install @electric-sql/pglite
PGLITE_MODULE=/absolute/path/node_modules/@electric-sql/pglite/dist/index.js node test/activity_database_test.mjs
```

`docs/previews`는 실제 Flutter 위젯과 Pretendard로 렌더링한 **테스트용 예시 데이터 화면**이다. 실제 운영 데이터나 실제 참가 이력이 아니다.

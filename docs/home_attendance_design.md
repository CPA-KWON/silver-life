# 출석을 중심으로 한 새 홈 (2026-10-25)

사용자가 제공한 세로형 홈 목업을 기준으로 날짜/포인트/프로필 → 인사말 → 출석체크 → 반려동물 → 다가오는 모임 → 동네 소식 → 더 둘러보기 순서로 구성했다. 메인 저장소 병합과 push는 하지 않는다.

## 연결 경로

| 홈 요소 | 동작 |
| --- | --- |
| 상단 포인트 | 기존 월별 출석 달력과 보유 포인트 |
| 내 정보 | 기존 프로필·회원정보·내 활동·기관 관리 |
| 출석 전의 출석 버튼 | 서버에 하루 한 번 출석 기록, 실제 포인트 갱신 |
| 출석 완료 버튼·주간 기록·출석 달력 | 같은 월별 출석 달력 |
| 반려동물 만나기 | 입양 전이면 기존 입양 화면, 입양 후이면 콩이 홈 |
| 다가오는 모임 제목 | 기존 모임 상세. 공개 모임에 참여 예정 상태를 임의로 붙이지 않음 |
| 승인된 예정 프로그램 | 실제 신청 프로그램 상세 |
| 모임이 없을 때 둘러보기 | 기존 동네 모임 목록 |
| 기관 공지 더 보기·공지 제목 | 실제 기관 공지 목록·상세 |
| 지역 커뮤니티 더 보기·글 제목 | 기존 커뮤니티 목록·상세 |
| 맞춤 활동 찾기 | 활동 탭의 기존 맞춤 조건/추천/프로그램 탐색 |
| 즐겨찾는 시설 | 저장한 시설 목록과 기존 시설 상세 |

반복되던 홈의 추천·미션·즐겨찾기 미리보기는 전용 화면 진입점으로 정리했다. 주간 미션, 신청 내역, 혜택 등 기존 기능은 활동과 내 정보의 전용 화면에 유지한다. 하단 다섯 탭과 지도 유지 구조는 바꾸지 않았다.

## 실제 기록

- 목업의 11P, 5회 출석, 3일 연속, +10P는 예시 숫자다. 화면에는 서버의 한국 날짜·지갑·출석 기록을 표시한다.
- 기존 출석 규칙을 유지한다. 일반 1P, 연속 7/14/30일에 3/5/10P. 목업을 이유로 서버 보상 규칙이나 데이터를 바꾸지 않는다.
- 월~일 발도장은 실제 attendance_days 조회로 표시한다. 연속 출석 수로 과거 출석을 추정하지 않는다. 주간에 월이 바뀌면 두 달 기록을 읽는다. 실패/로딩과 미출석을 구분하고 재시도를 제공한다.
- 기존 출석 지갑과 콩이는 같은 출석 기록을 사용한다. 입양한 콩이는 기존 pet_action을 통해 하루 한 번 10EXP를 받는다. 지갑의 출석 포인트를 중복 지급하지 않는다. 배경 조회와 출석이 겹치면 조회가 끝난 뒤 한 번 동기화한다.
- 원본의 웃는 성장 단계별 캐릭터 PNG를 홈 카드에 사용한다. 먹이 반응의 그릇 이미지를 홈 인사로 사용하지 않는다. 착용 중인 의상은 기존 레이어를 유지한다.
- 화면 크기와 큰 글씨 설정에 맞춰 줄바꿈하고, 좁은 화면/200% 글씨에서는 카드와 주간 기록을 세로로 재배치한다.

## 검증 범위

Flutter 정적 검사 오류 없음, 전체 테스트 113개 통과. 출석/포인트/달력/중복 지급 방지/모호한 응답 복구/월 경계/새 한국 날짜/주간 조회 실패/큰 글씨/배경 조회 중 성장 동기화 및 기존 로그인·지도 유지·활동·기관·모임·커뮤니티를 포함한다. Android 에뮬레이터의 실제 계정으로 표시와 진입 경로를 확인한다.

에뮬레이터의 일시적인 DNS 장애로 Supabase 로그인 갱신 오류가 보조 구독에서 처리되지 않던 점도 보완했다. 재시도 가능한 인증 오류에서는 현재 세션을 유지하고 실제 로그아웃 이벤트 처리는 그대로 보존한다.

이번 작업은 기존 서버 API와 RLS를 사용하므로 추가 SQL 실행이나 비밀키 설정은 필요하지 않다.

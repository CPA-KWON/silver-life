2. neighborhood_mockups.sql
3. neighborhood_media.sql
4. meetup_history.sql

이 서버에는 이미 적용됐다. 새 서버 설치 시에는 기존 통합 보안/활동/출석/반려동물/공지 기본 SQL을 먼저 적용하고 위 순서를 따른다. 기본 스키마 SQL을 기존 운영 서버에 다시 실행하지 않는다.

- 운영 조회 검사: activity_home/agency, 공지 목록/feed, 참여한 모임, 본인 기관 인증 요청, 시설 안내, 기관 초안 모두 200.

- 기관 승인: 실제 대표번호/담당자를 검증한 운영자가 SQL Editor 또는 비공개 서버에서 institution_review_access(request_id, approve, org_id, rejection_reason)를 사용한다. service_role을 앱에 넣지 않는다.

## 사용자/팀이 준비할 사항

1. 문자 인증: [Supabase Phone Login](https://supabase.com/docs/guides/auth/phone-login)에서 지원하는 발송 서비스를 선택하고 계정을 만든다. 한국 번호 발송 지원과 발신번호 설정을 확인한 뒤 Supabase Authentication의 Phone 공급자에 연결하고 실제 단말에서 발송/재전송/만료를 확인한다. 비밀키는 채팅이나 GitHub에 넣지 않는다. 현재는 계정이 없으므로 인증 준비 중이다.
2. 기관 검수: 인증 요청의 실제 재직/담당 여부를 확인할 운영자를 정한다. 기관을 시설에 연결한 후 프로그램·연락처·운영시간·층별 안내를 입력한다.
3. 광고 운영 ID/서버 SSV 배포, 푸시 메시지 서버 발송 설정, 실물 걸음 센서/화면 꺼짐 기록 검증은 별도 준비다. 화면/SDK가 있다는 이유로 실제 광고 수익·푸시 발송 검증 완료로 표시하지 않는다.
4. 레인코트 착용 자료와 성체 전용 산책 코스 자료는 사용자가 없다고 확인했다. 해당 해금 콘텐츠는 준비 중이다.

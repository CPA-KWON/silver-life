# 화면·버튼·DB 점검 결과

2026-10-17. v5 기준 코드를 보존하면서 활동 미션·경험 은행과 기존 화면의 연결 오류를 보완했다. 이전 로컬 커밋 `344fb51`이 재개 환경에 남아 있지 않아 대화의 확정 명세에서 변경분을 재구성했고, 아래 검사는 새 작업본에서 다시 수행했다. 이전 작업의 통과 수치를 재사용하지 않는다.

## 최종 검증 결과

- Flutter 3.47.7 / Dart 3.13.5.
- `flutter test --no-pub --concurrency=1`: **35개 통과**.
- `flutter analyze --no-pub lib test`: **지적 사항 없음**.
- PGlite에서 신규 migration 실행 및 권한·정원·미션·후원·할인·기관 처리: **44개 검사 통과**.
- `git diff --check`: 통과.
- 실제 Flutter 위젯의 활동 미션·경험 은행 화면을 한국어 폰트로 렌더링하고 이미지 확인.
- 네이버 `_SafeLocationTracker`는 공백을 제외한 내용이 기준 커밋과 동일함을 확인.
- 시/도 변경 후 시/군/구 선택 갱신도 실제 위젯 조작으로 확인. 해당 원본 코드는 변경하지 않음.

## 수정한 오류

- 홈·내 게시글·내 정보 새로고침의 `setState` 콜백이 Future를 반환하는 오류 수정. 상세·생성·회원정보 화면에서 돌아오면 목록과 프로필 갱신.
- 홈의 조회 일부 실패가 전체 영역을 가리지 않도록 분리. 실제 데이터가 없는 상태와 조회 실패를 각각 표시.
- 커뮤니티·모임의 최초 지역 조회 실패 시 무한 로딩 대신 재시도 제공.
- 화면 종료 후 비동기 결과로 상태·컨트롤러·안내를 갱신하지 않도록 mounted 확인. 중복 제출 방지.
- 지난 모임을 수정할 때 날짜 선택기의 initialDate가 허용 범위 밖으로 벗어나는 오류 수정. 기존 과거 일정을 유지한 내용 수정은 허용하되, 새 일정은 미래 날짜만 허용.
- 지도 위 시설·게시글·편집을 같은 Stack에서 유지. 장소 선택 시 편집 폼을 숨겨 보존하고, 돌아오면 입력 유지. 뒤로 가기는 현재 선택·편집·상세 순서로 처리.
- 시설 초기 조회 실패 재시도, 지도 검색 완료 시 컨트롤러 생존 확인, 시설 체크인 만료 시 주기적 인원 갱신.
- 주변 시설 조회에서 5분 넘게 지난 마지막 GPS 위치를 재사용하지 않음. 홈 새로고침 시 주변 시설도 갱신.
- 전화 앱 실행 실패 시 번호를 직접 확인할 수 있도록 안내.
- v5 카드의 색·반경을 유지하면서 Material을 제공해 ListTile·스위치의 잉크 레이아웃 오류 방지.
- 320px·글씨 2배에서 시설 체크인 버튼과 인원이 가로로 넘치는 오류를 줄바꿈 배치로 수정.

## 실환경 확인이 필요한 항목

1. 실제 Supabase의 권한·스키마·가입 이메일 인증·실데이터 기반 전체 흐름. 실제 프로젝트에 접속하거나 SQL을 적용하지 않았다.
2. Android/iOS 실기기의 네이버 지도 인증·타일·마커·카메라, 위치 권한 허용/거부/영구 거부, 위치 서비스 꺼짐, 이동 중 GPS·앱 전환·복귀.
3. 실제 전화 앱으로 연결되는 동작. 자동 검사는 실행 실패 시 안내를 확인했다.
4. 여러 실제 계정·동시 요청의 통합 검사. SQL 잠금·정원 처리는 검증했으나 실제 네트워크 동시 부하 검사를 수행하지 않았다.
5. `supabase/schema.sql`의 profiles 조회 정책은 본인 프로필만 허용한다. 실제 서버도 이 정책만 사용한다면 `profiles!inner`가 있는 지역 커뮤니티에서 다른 작성자 글이 누락될 수 있다. 실서버 정책을 확인하지 않았고, 이름·출생년도까지 공개할 수 있는 무분별한 권한 확대는 하지 않았다.

실제 결제·정산과 팀 신규 커밋 병합은 수행하지 않았다. 원본 팀 main과 개인 저장소 main은 수정하지 않는다. 최종 작업본은 사용자 승인으로 hangyul0504-droid/silver-life의 feature/activity-missions-experience-bank 브랜치에 업로드한다.

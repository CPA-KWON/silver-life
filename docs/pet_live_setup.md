# 콩이 v3 — 화면·실제 저장 연결 (2026-10-25)

현재 브랜치 `feat/pet-companion-v3`. main 병합·push하지 않음.

## 적용 범위

홈 반려동물 카드 → 입양 → 콩이 홈 → 간식 선택/구매/먹는 반응/완료 팝업, 옷 미리보기/구매/입히기/벗기기, 산책 시작/진행/일시정지/완료/보상, 성장 준비/전환/축하, 성장 기록/달력/이름 변경, 오늘의 출석/주간 3단계/기관 완료 보상/광고 진입.

원본 PNG와 분리된 그림자·의상 레이어를 사용하고, 화면을 실제 버튼과 레이아웃으로 구성했다. 화면 전체 이미지를 터치 영역으로 덮는 방식이 아니다. 화면 크기·접근성 글자 확대에 따라 줄바꿈과 높이는 달라진다.

- 기본 캐릭터 화면: 디자이너가 제공한 원본 PNG 및 아기 인사 프레임.
- **좌우로 돌리기**: 기존 오프라인 GLB 모델을 별도 입체 보기로 유지. 카메라 상하 회전·확대는 잠김. 원본 Blender/GLB가 없어 원본 캐릭터와 3D 모델의 외형은 완전히 같지 않다.
- 의상: 모자·줄무늬 니트·꽃핀은 원본 분리 레이어. 겨울 니트는 별도 원본이 없어 기존 니트를 색 변환해 표시한 임시 외형이다.
- 레인코트 착용/성체 전용 코스는 추가 자료가 없다는 사용자 답변에 따라 준비 중. 해금된 실제 콘텐츠라고 표시하지 않는다.
- 원본 동작에는 의상을 입은 먹기 프레임이 없어 먹는 반응 중에는 기본 모습, 완료 뒤에는 저장된 의상을 다시 보여준다.

## 실제 서버 적용

1. Supabase 프로젝트 `xshsevpsuhtzfmorfnzy` → **SQL Editor → New query**.
2. `supabase/pet_companion.sql` 전체 붙여넣기 → **Run**.
3. 결과 확인. SQL은 한 트랜잭션이며 재실행 가능. 기존 `attendance_points.sql`, 활동 테이블이 먼저 필요하다.
4. 앱 → 홈 → 반려동물 만나기 → 다시 연결하기. 연결되면 실제 지갑/반려동물 상태를 읽는다.

2026-10-25 사용자가 SQL 실행 성공을 확인했고, 운영 `pet_state` 응답 200을 검증했다. 승인된 ins 검증 계정에서 입양·출석·무료 사료·간식 사용을 실제 저장하고, 별도 재로그인 상태가 일치함을 확인했다. 지갑 1P, 경험치 15EXP. 직접 DB 쓰기·다른 사용자 조회·확인되지 않은 프로그램/광고 보상·잔액 부족 구매·중복 출석을 실제 API로 차단 확인했다. 프로그램 참여 완료 보상의 양성 사례와 실제 센서/광고는 별도 검증이 남아 있다. 미설정 서버에서는 실제 보상을 주는 척하지 않고 연결 안내를 표시한다. ‘디자인 미리보기’는 별도 임시 메모리로 실제 포인트와 섞지 않는다.

## 서버 보상 규칙

- 기존 출석: 일반 1P, 연속 7/14/30일 3/5/10P 그대로 유지. 콩이 오늘의 활동에서 출석 보상 확인 시 하루 10EXP 추가. 이미 출석했으면 포인트를 다시 지급하지 않는다.
- 무료 사료 하루 3번, 배부름 +1. 고구마 간식 입양 선물 2개, 배부름 +2/5EXP. 우유 껌 50P/+1/10EXP, 케이크 120P/+3/20EXP.
- 아기 200EXP → 사용자가 ‘성장시키기’를 눌러 성장기. 누적 500EXP → 성체. 옷 구매 자체는 성장 경험치를 주지 않는다.
- 기관이 완료 처리한 본인 프로그램: 신청 건당 200P/50EXP 한 번. 신청·승인만으로는 지급하지 않는다.
- 콩이 주간 미션: 한국시간 월요일 시작, 출석 3일(10EXP) → 함께 참여하는 프로그램 완료 1회(100P) → 프로그램 완료 1회(30EXP). 앞 단계부터 보상 수령. 기존 활동 추천의 프로그램별 주간 미션은 덮어쓰지 않는다. 현재 동네 모임에는 참여 완료 기록이 없으므로 ‘함께 활동’ 실적은 기관 프로그램 완료 데이터를 사용한다.
- 산책: 시작 후 2,000걸음 또는 DB에 등록된 시설 100m 안에서 2분 체류. 하루 30P/10EXP. 시간·거리·위치 정확도·중복 보상은 서버에서 확인한다.
- 위 수치는 목업의 임시 숫자를 토대로 이번 구현에 적용한 초기 정책이다. 경제성/활동 분포에 따른 조정은 별도다.

## Android 산책

첫 출시에서는 포그라운드 서비스를 뺐다. 앱 화면이 켜져 있을 때만 기록하며(docs/pet_walk_background.md), 아래 설명은 다시 켰을 때 기준이다. 사용자가 산책을 시작하면 걸음 수/위치 권한을 요청하고, 산책 알림을 띄우는 포그라운드 서비스를 실행한다. 센서의 시작 이후 증가분과 진행 상태를 기기에 보존한다. 화면을 꺼도 서비스가 유지되는 동안 기록한다. 위치 방문 확인은 앱을 다시 열어 서버와 동기화할 때 이어진다.

걸음 센서 없는 기기는 시설 방문 대안을 사용한다. 실제 걸음 기록/화면 꺼짐/배터리 최적화 동작은 **실물 Android 기기에서 추가 검증 필요**. 강제 종료·제조사 절전·기기 재부팅 상황의 무손실 기록을 보장하지 않는다. 기기에서 올라오는 걸음 수는 서버에서 속도·시간을 검사하지만, 변조된 기기의 센서 조작까지 막는 검증(Play Integrity 등)은 아직 없다.

## 보상형 광고

Google Mobile Ads SDK 및 서명 확인 코드 준비. 아직 AdMob 운영 계정/단위와 웹훅 배포가 필요하다.

1. AdMob에서 Android 앱과 보상형 광고 단위를 만든다. 앱 ID와 단위 ID는 공개 설정이며 관리자 비밀키와 다르다.
2. 서버 함수 `pet-admob-ssv`에 `index.ts`, `verify.ts` 배포. Google 콜백에는 로그인 JWT가 없으므로 config.toml의 verify_jwt=false를 사용한다. 대신 Google ECDSA 서명 검증을 통과해야 한다. service_role 키는 서버 런타임에만 사용한다.
3. 광고 단위 SSV 주소를 `https://xshsevpsuhtzfmorfnzy.supabase.co/functions/v1/pet-admob-ssv`로 설정한다.
4. `pet_config`의 `admob_unit`에 실제 단위 ID를 관리자로 설정한다. 빈 값인 동안 실제 광고 보상 시작은 차단한다.
5. 실제 배포 빌드: 환경 변수 `SILVER_LIFE_ADMOB_APP_ID`와 Dart define `PET_REWARDED_AD_UNIT` 설정. 기본 개발 빌드는 Google 공식 테스트 앱/광고 ID를 사용한다. 테스트 광고로 실제 지갑 포인트를 지급하지 않는다.
6. 실제 단위의 Google SSV 확인 → `pet_verify_ad` → 본인 `ad_claim` 순서 검증 후 운영. 30P, 한국 날짜 기준 최대 2번. 지연 확인된 보상은 다시 열어 수령 가능.

공식 기준: https://developers.google.com/admob/flutter/rewarded , https://developers.google.com/admob/android/ssv

## 권한·실패 처리

새 표는 본인 읽기만, 쓰기는 로그인한 본인 RPC. 다른 사용자 UUID를 받는 내부 함수는 외부 호출을 금지한다. 지갑 잠금으로 동시 요청을 직렬화하고, 요청 UUID 재사용·활동별 참조 중복 방지로 이중 차감을 막는다. 실패한 구매는 잔액과 소유권이 모두 롤백된다. 광고는 클라이언트 완료 콜백만으로 지급하지 않는다.

기존 지도 유지 구조는 변경하지 않았다. 전체 화면도 로그인 사용자의 Navigator에 속해 로그아웃하면 제거된다.

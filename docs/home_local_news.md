# 홈과 동네 소식 (2026-10-25)

현재 브랜치 feat/pet-companion-v3, main 병합/push 없음.

## 화면

오른쪽 수정 목업의 인사/원형 프로필 → 입양 전후 반려동물 카드 → 다가오는 모임 → 동네 소식 구조. 빈 주간 현황은 화면을 차지하지 않으며, 실제 미션/예정 활동이 있을 때만 아래에 작게 요약한다. 추천/즐겨찾기/출석 기능은 그대로 진입할 수 있다. 하단 5개 탭과 지도 유지 구조를 보존한다.

다가오는 모임은 기존 동네 모임처럼 시설 지역+미래 일정으로 조회한다. 공개 모임에 사용자의 참여 상태를 임의로 붙이지 않는다. 기관 프로그램의 실제 승인 내역만 참여 예정으로 표시한다.

동네 소식 카드에서 기관 공지와 지역 커뮤니티 글을 분리하고 각 2개까지 표시한다. 공지는 기관 공지 상세, 커뮤니티는 기존 게시글 상세로 열린다. 각각 전체 목록 진입이 있다. 없음과 요청 실패를 구분하고 재시도를 제공한다.

## 기관 공지 서버

추가 파일: supabase/institution_notices.sql. 기존 기관/담당자 권한과 회원 지역을 사용하며 기존 테이블/RLS/데이터는 바꾸지 않는다. **운영 적용은 사용자 SQL Editor 실행 대기**.

승인된 기관 담당자가 내 정보 → 기관 관리 → 프로그램 관리 → 기관 공지 관리에서 작성한다. 새 글은 항상 비공개이며 제목/본문/대상 시도·시군구/선택 HTTPS 원문 링크/선택 종료일을 저장한다. 내용을 확인하고 게시하기를 누르면 해당 지역 이용자의 홈에 표시된다. 게시 중지/종료일 경과 시 공개 조회에서 빠지고 기관 기록에는 남는다. 다른 기관의 수정/게시와 일반 사용자의 직접 쓰기를 차단한다. 작성자 개인 UUID는 공개하지 않는다.

여기서 공식 공지는 승인된 기관 담당자가 기관 명의로 등록하는 공지다. 보건소·복지관 홈페이지 자동 수집이나 별도 외부 API 연동은 포함하지 않는다. 실제 공지가 없는 상태에서 예시 공지를 채워 넣지 않는다.

## 검증

- Flutter 전체 테스트 102개: 새 홈 빈 상태/오류 재시도/기존 상세 연결/기관 공지 구분/작성·비공개 저장/명시적 게시·중지/입력 보존과 HTTPS 검증. 기존 로그인/지도 상태 유지/활동/모임/커뮤니티 회귀 포함.
- tool/test_notices_sql.mjs: 격리 PostgreSQL에서 SQL 설치·재실행, 지역 조회, 비공개/만료 숨김, 승인 기관 소유권, 직접 쓰기/비로그인/작성자 UUID 조회 차단 검증.
- Android 에뮬레이터에서 ins 로그인 → 새 홈 → 콩이 화면(실제 1P/15EXP 보존) → 내 정보 → 기관 관리 진입 확인. 최신 실행 로그에 Flutter 예외/레이아웃 넘침/앱 종료 오류 없음.
- 실제 회원 지역의 기존 모임/커뮤니티 조회 API는 200/현재 0개 확인. 운영 기관 공지 RPC는 SQL 적용 후 확인 필요.
- pet_companion.sql은 별도이며 사용자가 이미 실행 성공, 운영 API 저장/권한 검증 완료.

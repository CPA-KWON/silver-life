# Silver Life 반려동물 확장 — 디자이너 요청서 및 개발 준비안

2026-10-29 · 새 목업 제작 요청 · 기존 앱 화면과 비교하여 제작

이번 문서는 새 기능의 설계·개발 준비안입니다. 고양이·안전 산책·새 아이템·Google Play 현금 결제가 구현되었다는 뜻은 아닙니다. 현재 화면은 첨부 캡처의 날짜와 실제/미리보기 표시를 확인해주세요.

## 1. 디자인 공통 기준

기존 목업의 연한 하늘색 배경, 큰 글씨, 둥근 카드, 파란 핵심 버튼, 보라색 성장 보상을 유지해주세요. 산책은 민트 계열을 사용합니다. 한 화면의 핵심 행동은 하나로 하고, 중첩 가로 스크롤은 피해주세요. 상태를 색만으로 구분하지 말고 글자와 아이콘도 함께 표시해주세요.

Android 기준 가로 430 논리 px의 기준 시안과 작은 화면/큰 글씨 변형을 주세요. 핵심 본문 18–20sp, 터치 영역 최소 48dp를 설계 목표로 합니다. 산책 중 전화·일시정지·종료는 스크롤하지 않아도 접근할 수 있어야 합니다. 길게 누르기나 드래그만으로 필수 기능을 실행하게 하지 않습니다.

기존 하단 5탭(홈·시설 찾기·활동·동네 모임·커뮤니티)을 유지합니다. 산책 진행 화면은 오조작을 줄이기 위해 집중 화면으로 구성하고 뒤로 가도 기록 상태가 보존됨을 안내합니다. 캐릭터 회전은 좌우만, 카메라 높이·거리는 고정합니다. 동작 줄이기 상태도 고려해주세요.

## 2. 산책 안전 기능 — 요청할 목업

현재 산책은 시작/진행/일시정지/종료/보상과 걸음·시설 방문 확인이 있습니다. 아래 지도·연락처·귀가 시간은 신규입니다.

W01 산책 시작 전: 캐릭터와 오늘 목표, 선택한 목적지, 지정 연락처 요약. ‘휴대폰을 챙겼나요?’, ‘밝고 익숙한 길로 걸어요’, ‘불편하면 쉬어가요’의 짧은 안내. 연락처·목적지·귀가 시간은 선택이며 미등록이어도 산책 가능. 핵심 버튼 ‘산책 시작하기’. 준비 안내 확인 자체로 보상하지 않습니다.

W02 연락처 등록/수정: 이름·관계(선택)·전화번호를 직접 입력, 등록 전 번호 확인, 저장·삭제·번호 없음·입력 오류 상태. 기기 연락처 전체 접근 없이 수동 등록을 기본으로 합니다. ‘가족·지인에게 전화’라고 표시하고 자동 구조 요청으로 오해하지 않게 합니다.

W03 목적지 선택: 기존 시설 검색/목록/지도 연결. 시설명·주소·현재 위치에서의 직선거리·위치 확인 시각. ‘목적지 없이 걷기’ 제공. 목적지 삭제·변경 가능. 기존 시설 지도 상태를 지키고, 산책 지도는 진행 화면에서 지연 생성합니다. 보행 경로가 없으면 선을 그어 안전 경로처럼 표시하지 않습니다.

W04 귀가 예정 시간: 선택 시간·건너뛰기·수정. 시간이 지나면 본인 화면/허용된 기기 알림으로 ‘괜찮으세요? 잠시 쉬거나 연락해보세요’. 자동 보호자 전송이나 구조를 약속하지 않습니다. 알림 권한 거부/앱 중단 때의 제한 안내도 필요합니다.

W05 산책 중: 걸음 수·목표·경과 시간과 실제 기록 상태가 먼저 보이게. 지도 접기/펼치기, 내 위치·목적지, 최근 위치 확인 시각. 하단 고정 ‘가족·지인에게 전화’, ‘일시정지’, ‘산책 종료’. 전화 앱을 열며 산책은 유지. 연락처 없음은 등록으로 연결. 지도/센서 실패가 전화 버튼을 막지 않게 합니다.

W06 일시정지/종료: 멈춘 상태와 경과 시간 규칙, 이어 걷기, 목표 전 종료 확인. ‘오늘은 여기까지 해도 괜찮아요’ 문구. 보상 조건 미달이면 기록은 남기고 보상 여부를 명확히 표시하도록 신규 이력 설계를 합니다.

W07 완료/기록: 실제 걸음 수·시간·목적지 달성 여부, 30P·10EXP 하루 1회(현행 기준), 이미 수령/확인 중 상태. ‘결과 공유’는 사용자가 공유창에서 직접 선택하는 후속 기능으로 설계. 공유 전 정보 미리보기, 좌표·집 주소·연락처 기본 제외.

W08 예외 상태 모음: 위치 거부·영구 거부·정확도 낮음·GPS 오래됨·센서 미지원·알림 거부·오프라인·앱 재시작/기록 복구·보상 대기·전화 앱 없음. 걸음 수 대안과 시설 방문 대안의 사용 가능 여부를 각각 표시. 화면 꺼짐/재부팅/제조사 절전은 실물 Android에서 검증한 범위만 안내합니다.

현재 완료 조건은 산책 시작 후 2,000걸음 또는 등록 시설 100m 이내 2분 체류입니다. 2,000걸음은 앱 보상 기준이며 개인별 건강 권장량으로 표현하지 않습니다. 선택 목적지와 서버가 확인하는 보상 대상 시설의 관계를 개발 시 명확히 하고, 목적지만 지정했다고 방문 완료로 표시하지 않습니다.

이번 범위는 지도·연락·기록 상태를 통해 산책을 돕는 기능입니다. 실시간 위치 공유, 보호자 자동 알림, 낙상 감지, 안전 경로 보장은 별도 프로젝트로 둡니다. 경고 문구를 매 화면 길게 반복하지 않습니다.

## 3. 고양이 — 요청할 목업과 원화

C01 입양 선택: 강아지 콩이/고양이(이름 미정) 2개 카드, 큰 이미지·간단 소개·선택 표시. 선택 후 이름 짓기와 확정. 캐릭터 미선택/이름 오류 상태 포함.
C02 고양이 성장 3단계: 아기·성장기·성체의 정면/좌우/뒤/사선 원화. 귀·꼬리·눈·체형의 차이를 설명하고 같은 캐릭터로 이어지게 합니다. 기존 강아지와 같은 앱 스타일을 유지합니다.
C03 고양이 홈/돌봄: 인사·대기·먹기·걷기·기쁨·성장 축하 상태. 먹이 이름/그릇/아이콘도 고양이에 맞게 검토합니다. 기존 강아지용 ‘우유 껌’을 무조건 복제하지 않습니다.
C04 성장 전환/기록: 아기→성장기→성체 비교와 해금 아이템, 실제 달성 날짜·함께한 기간·활동 기록. 성장 조건은 기존 누적 200/500EXP 유지 제안입니다.
C05 기존 이용자: 기존 콩이·의상·P·EXP·기록 보존. 신규 이용자만 최초 종류 선택을 기본으로 하고, 기존 이용자의 종류 변경/둘째 입양은 정책 확정 전 제공하지 않습니다. 포기/재입양으로 데이터 초기화시키지 않습니다.

한 계정 한 마리 구조를 우선 유지합니다. 두 동물을 함께 기르는 화면이나 친구 방문은 이번 요청 범위에 포함하지 않습니다.

고령자 선호가 검증된 디자인이라고 표현하지 말고 위 제안을 시안으로 만들어 실제 시니어에게 이름 인지·선택·착용·구매 구분을 확인해주세요.

## 5. 상점·광고·현금 결제 — 요청할 목업

S01 옷장/상점: ‘내 옷장’과 ‘새 아이템’ 구분. 종류(의상/장식)와 획득 방식(P/특별 구매/활동 선물)을 짧게 표시. 보유·착용 중·성장 잠금·다른 동물 전용 구분. 고양이에게 강아지 전용을 구매시키지 않습니다.
S02 아이템 상세: 좌우 회전 미리보기, 이름·설명·지원 동물·성장 단계, 확정된 획득 방법. P 상품에는 ‘150P로 구매’ 같은 표기, 현금 상품에는 Play가 반환한 현지 가격과 ‘Google Play로 구매’ 표기. P와 원을 섞어 보이지 않습니다.
S03 P 구매 확인/부족: 가격·보유P·구매 후 잔액, 구매/취소. 부족할 때 ‘활동으로 모으기’와 광고 운영 가능 시에만 ‘광고 보고 30P 받기’. 보유 아이템은 ‘입히기’로 표시.
S04 광고 보상: 사용자 선택 ‘광고 보고 30P 받기’, 오늘 남은 횟수(기존 하루2회), 준비 중·광고 없음·중도 종료·보상 확인 중·완료·이미 수령·나중에 다시 확인. 실제 광고 내용/길이는 광고 SDK가 결정하므로 별도 광고 화면을 앱 디자인으로 복제하지 않습니다.
S05 현금 구매 전후: 구매 내용·지원 종·단계·가격·영구 소장 여부, Play 기본 결제창 호출. 앱 내부에 카드번호 입력 UI를 만들지 않습니다. 결제 대기·사용자 취소·실패·구매 확인 중·검증 완료·중복 소유 상태 요청.
S06 보유 아이템 복원/문의: ‘구매한 아이템 다시 확인’, 복원 중·완료·다른 앱 계정 귀속 안내·오프라인. 환불/취소 확인 중 표시, 도움말·구매 내역 진입. 결제 성공 전 장착/포인트 지급하지 않습니다.
S07 활동 선물: ‘첫 산책 완료로 받았어요’ 같은 기념 아이템 지급, 중복 보상 방지, 옷장으로 이동. 의상 구매 자체는 성장 EXP를 올리지 않습니다.

권장 흐름: 활동/선택형 광고→P→일반 아이템 구매 / Google Play→특별 의상·장식 영구 소장. 초기에는 현금으로 P를 충전하는 기능을 제외해 재화 혼동을 줄입니다. 특별 아이템은 외형 차이만 제공하고 산책 안전 기능·기본 돌봄·성장 기회는 무료 유지합니다. 랜덤 뽑기·자동 구독은 이번 제안에 넣지 않습니다.

광고 1회로 옷을 즉시 주는 방식은 별도 보상 정책이 필요하므로 초기에는 기존 30P 보상 방식을 유지합니다. 예를 들어 150P 아이템은 다른 수입이 없으면 광고5회가 필요하고, 하루2회 한도라 최소3일이 걸립니다. 기존 출석·산책P도 사용 가능하며 실제 가격은 현재 이용자의 수입 분포를 보고 정합니다.

## 6. 3D 제작 전달물

디자이너는 화면 원본(Figma 또는 레이어 원본)과 PNG를 전달해주세요. 캐릭터/의상 앞·뒤·옆·사선 시트와 착용 위치 표시가 중요합니다. 스크린샷 한 장만으로 360도 외형·먹기/걷기 변형을 동일하게 복원할 수는 없습니다.

3D 제작은 사용자가 별도로 방법을 확인하는 것으로 알고 있습니다. 모델러에게는 고양이 성장3단계 GLB/Blender 원본, 모델별 리그와 파츠 분리, Idle/Jump/Walk/Eat/Happy 클립, 의상 장착 지점·변형 규칙을 전달해야 합니다. 이번 설계안은 Happy를 신규 요청하고 나머지4개는 기존 콩이 클립명과 맞춥니다. 프레임별 PNG 대체도 따로 제공하되 실제3D 회전은 GLB가 필요합니다.

상하 회전 제한 유지. 귀·꼬리·의상 관통, 걷기/먹기 중 탈착 위치, 성장 전후 피팅, 중저가 Android의 로딩·프레임을 검증합니다. 제작 성능 예산은 실제 기기 프로파일링 후 정합니다.

## 7. 개발 착수 준비 — 현재 코드 확인 결과

현재 존재: pet_walk_page.dart / pet_walk_service.dart의 Android 센서·위치 기록, 기존 시설 지도, url_launcher 전화 연결 기반, 강아지 baby/junior/adult GLB, 고정 의상 목록, P 구매 RPC, PetAdsService와 SSV 서명검증 코드.
현재 없음: 고양이 species 필드·신규 고양이 모델, 산책 지정 연락처·목적지·귀가 시간 UI, 동적 아이템 카탈로그·동물별 소유권, Google Play Billing 의존성·상품·서버 구매 검증. 광고 운영 단위/SSV 배포는 별도 확인과 설정이 필요합니다. SDK 코드가 있다는 이유로 광고가 운영된다고 표시하지 않습니다.

개발 순서:
1. 산책 연락처·목적지·진행 상태 모델/로컬 저장과 UI. GPS 실패·전화 실패·재시작·화면 꺼짐 테스트. 연락처는 기기 내 본인 설정으로 먼저 저장하고 자동 전송하지 않음.
2. species=dog 기본값을 추가하는 확장 마이그레이션 설계. 기존 콩이 상태·지갑·이력 보존. 하드코딩 아이템 제약을 서버 카탈로그/호환 규칙으로 대체하고 기존 hat/knit/winter/flower ID와 소유권을 보존. 신규 ID는 별도 파일에 고정.
3. 고양이3단계와 20아이템 적용. 보유/미리보기/장착 상태 분리, 슬롯 충돌과 성장 잠금 검증.
4. 보상형 광고 운영: 테스트 ID→운영ID 설정, Google 서명검증 콜백·사용자 세션·트랜잭션 중복 차단·하루2회 한도 확인. 테스트 광고는 실제 지갑을 적립시키지 않음.
5. Play 테스트 결제: 콘솔 상품·테스터·내부 테스트 배포, Flutter Billing 연동, 서버 구매검증/확인 처리/환불 회수/복원 후 실판매 준비.

서버 설계안: pet_item_catalog(종·슬롯·단계·획득법), pet_store_products(Play상품과 아이템 묶음 연결), pet_purchase_receipts(토큰 고유·구매계정·상태), pet_entitlements(획득 출처별 권한). 실제 이름은 구현 때 확정합니다. 사용자 직접 잔액·소유권 수정은 RLS로 금지하고 서버에서 검증합니다.

현금 상품은 일회성 비소모성 영구 의상으로 제안합니다. 앱 내 로그인 계정과 Play 계정 귀속을 서버에서 확인하고 토큰 재사용을 막습니다. P로 이미 얻은 아이템이나 다른 구매로 얻은 권한은 환불 회수 시 함께 지우지 않습니다. 대기 중은 지급하지 않고 PURCHASED와 검증 완료 후 지급·구매 확인 처리, 환불/취소는 Google 서버 알림/API로 재검사합니다.

실제 판매 준비: Play Console 소유자 권한, 결제 판매자 설정, 일회성 상품 ID/가격/국가, 내부 테스트 트랙·라이선스 테스터, 서버 전용 API권한/비밀설정. 비밀키는 채팅·GitHub·앱에 넣지 않습니다. 이 문서 생성으로 상품 등록·결제 배포·DB 변경을 수행한 것은 아닙니다.

검수: 기존 강아지 데이터 보존, 큰 글씨, 연락처 없음·오프라인에도 산책 중단 가능, 실제 걸음 기록(실기기), 동일 광고/구매 재시도 중복 차단, 결제 취소/보류/환불/재설치 복원, 옷 착용/해제/종별·성장별 피팅을 확인합니다.

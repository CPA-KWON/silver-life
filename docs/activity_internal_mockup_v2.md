# 활동 내부 페이지 목업 v2

사용자 제공 `/Users/han/Downloads/활동_내부페이지_목업_v2`의 A~H 및 Z 화면을 기준으로 기존 활동 기능을 재구성했다. 작업 브랜치는 `feat/activity-hub-mockup`. main 병합·push 없음.

기관 관리도 추가 정보를 입력하고 수신하도록 연결했다. 기관 프로그램 등록에서 대상·준비물·층별 안내를 입력할 수 있고, 신청자 화면에서 제출 메모·경험 사본과 반려 사유를 확인한다. 개인정보 열람 범위를 넓히지 않는다.

## 서버 설정

1. `supabase/activity_mockup_v2.sql`: 사용자 SQL Editor 실행 성공 보고 후 실제 서버에서 새 표·필드 읽기와 함수 존재, 비로그인 차단 확인. 기존 데이터·기존 RLS 유지. 새 관심 프로그램 표는 본인만 읽기/쓰기.
2. `supabase/activity_program_mission_rewards.sql`: G 화면의 별도 단계별 보상. 1단계 50P, 2단계 100P, 3단계 30EXP. 콩이 입양 및 현재 주의 해당 미션 참여 완료가 필요하다. `(사용자, 한국시간 주, 단계)` 참조로 중복 지급을 차단하고 기존 지갑·기록과 같은 트랜잭션에 기록한다. 사용자 실행 Success 보고 후 운영 함수 존재·잘못된 단계/비로그인 차단을 읽기 확인했다.

신청은 `activity_apply_with_note`가 기존 신청 함수를 내부 호출하므로 기존 정원·마감·본인 경험·활성/같은 분야 검사와 금액 계산을 유지한다. 빈 메모로 재지원할 때도 이전 메모와 반려 사유가 초기화된다. 기관 메시지는 200자, 반려 사유는 300자 제한.

미션 교체는 기존 추천 반경·관심·이동수단·시간·난이도·단계별 장소/함께 활동 기준을 재검사한다. 앞뒤 미션의 시간 순서와 기존 신청·완료 이력을 보호한다.

## 원본의 예시와 실제 데이터

- 목업의 예시 프로그램·기관·인원·날짜를 운영 DB에 만들지 않았다. 실제 모집 데이터가 없으면 원본의 빈 화면을 표시한다.
- 실제 경로/분 단위 이동시간이 없으므로 `도보 12분` 같은 예시를 계산한 것처럼 표시하지 않는다. 표시 거리는 기존 서버 좌표 기반 직선거리다.
- 층별 안내·대상·준비물이 미등록이면 등록되지 않았다는 안내를 제공한다. 임의 정보를 채우지 않는다.
- 기존 20km, 30분·4시간 선택도 보존한다. 시간 ‘무관’은 기존 서버 최대 허용치인 8시간, 난이도 ‘무관’은 기존 1~3 전체를 뜻한다.
- 기존 프로그램 실제 참여 보상(200P·50EXP), 콩이 주간 보상(10EXP·100P·30EXP), 프로그램별 주간 보상(50P·100P·30EXP)은 서로 다른 완료 조건과 중복 방지 참조를 쓴다. 신청 자체에는 지급하지 않는다.
- 프로그램별 미션 보상은 기관 완료 확인 후 이용자가 ‘미션 보상 받기’로 수령한다. 받은 단계는 지급 완료 상태로 바뀐다.
- 실제 Android 캡처는 `outputs/activity-internal-v2-20261028/0*-live-*.png`. `preview-*`는 격리된 예시 데이터로 같은 Flutter 화면을 렌더링한 검증용 이미지이며 실제 모집이 아니다.

## 검증

- Flutter 전체 134개 회귀 테스트 및 새 동선 테스트 통과: 지도 객체 유지, 로그인/로그아웃, 홈/프로필/커뮤니티/모임, 신청·취소·지원·기관 처리, 필수 입력, 관심 저장, 단계 교체, 보상 중복, 처리 중 중복 제출, 320px/큰 글씨 2배.
- `test/activity_database_test.mjs`: 기존 44개 DB 검증.
- `test/activity_mockup_database_test.mjs`: 새 SQL 반복 적용·RLS·개인 제출 스냅샷과 메모·기관 권한·반려 사유·일정/신청 보호·프로그램별 보상/중복 차단 검증.
- 운영 서버 읽기 확인: 활동 홈·기관·콩이, 새 필드·관심 표·기존 혜택, 잘못된 미션 단계와 비로그인 접근 차단. 실제 사용자의 신청·포인트를 검증용으로 변경하지 않음.
- 프로그램 모집 데이터가 없는 현재 운영 계정에서는 신규 신청~기관 완료의 양성 흐름을 운영 서버에서 끝까지 실행하지 않음. 격리 DB와 Flutter 동선에서 검증하며 실제 모집 생성·계정 준비 후 운영 현장 검증이 필요하다.
